# **Fact & Claim Verification System**

### **Background & Context**

The rapid proliferation of AI-generated content and digital news has led to a surge in misinformation and LLM "hallucinations." Manually fact-checking every statement in dense documents or automated outputs is labor-intensive and unscalable. This creates a critical need for automated tools to ensure content reliability, trust, and compliance in enterprise environments.

### **Business Problem Statement**

Develop an AI-driven fact-checking engine that validates text integrity against real-time data. The solution must execute the following pipeline:

1. **Claim Extraction:** Decompose complex input text (articles, essays, URLs) into discrete, verifiable statements.  
2. **Evidence Retrieval:** Integrate a web search tool to autonomously formulate search queries, fetch real-world sources, and cross-reference them against the extracted claims.  
3. **Verification & Reporting:** Compare claims against the retrieved evidence to determine validity (True/False/Partially True/Unverifiable) and generate a granular Accuracy Report complete with explicit citations and confidence scores.

### **Expected Deliverables**

* A working prototype (Web App) that takes a plain-text input or a URL of a news article, runs the multi-step verification pipeline, and presents a detailed, interactive accuracy report.  
* A link to the public GitHub repository.  
* A 10-minute presentation showcasing the tool processing at least three distinct URLs/texts with varying degrees of factual accuracy, including a scenario with conflicting web evidence.

### **Recommended Tech Stack**

* **Frontend:** React, Next.js, Vue, or rapid-prototyping frameworks like Streamlit or Gradio.  
* **Backend and API:** Python (FastAPI, Flask) or Node.js (Express).  
* **LLM & Orchestration:** Google Gemini API alongside agentic frameworks like LangChain, LlamaIndex, or AutoGen.  
* **Search Integration:** Google Custom Search API, Tavily, SerpApi, or DuckDuckGo Search.

### 

### **Evaluation Framework**

**Accuracy (40)**

* **Claim Extraction:** Did the LLM correctly isolate verifiable atomic facts without losing the original contextual meaning?  
* **Evidence Retrieval:** Did the system formulate effective search queries and retrieve highly relevant, authoritative sources?  
* **Verification Logic:** How accurately did the system classify the claims based *only* on the retrieved evidence, avoiding internal hallucinations?

**Aesthetics (30)**

* **Explainability (UI):** Does the interface clearly and visually map the original text to the extracted claims and their corresponding cited evidence?  
* **User Flow:** Is there a clear progress indicator or streaming output for the multi-step agentic process (Extracting \-\> Searching \-\> Verifying)?  
* **Design:** Is the final accuracy report clean, modern, and easy for a non-technical user to digest?

**Approach & Innovation (30)**

* **Architecture:** How robust is the multi-agent pipeline? Does the system successfully recover from failed searches or API rate limits?  
* **Handling Ambiguity:** How gracefully does the application handle conflicting sources, highly ambiguous claims, or temporally sensitive facts (e.g., "The current CEO is...")?  
* **Prompt Engineering:** Did the team use advanced techniques (like Chain of Thought or self-reflection) to ensure the verification agent accurately justifies its reasoning?

### **Bonus Points**

* **AI-Generated Text Detection (10):** Implement a mechanism to analyze the input text and calculate a probability score indicating whether the content was generated by an LLM versus written by a human.  
* **AI-Generated Media Detection (20):** Extend the detection capabilities to analyze associated non-text media (e.g., images or audio embedded in the URL or document) to determine if they are AI-generated or synthetically manipulated deepfakes.
